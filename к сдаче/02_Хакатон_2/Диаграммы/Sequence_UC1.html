1. выбирает врача, дату и слот
2. POST /api/v1/appointments/me
3. создать запись
4. проверить слот и пациента
5. свободно
6. insert appointment + operation
7. created
8. 201 Created
9. показать запись
Как читать: сплошная стрелка — вызов, пунктирная — ответ. Записи проверяют слот и отсутствие второй активной записи пациента; при конфликте API отвечает 409. Создание записи и операция журнала сохраняются в одной транзакции. Повторный запрос того же пациента возвращает существующую запись (200, replayed=true).
Источники: ПЗ №3 (UC-1), ПЗ №6 (компоненты «Записи», «Расписание»), ПЗ №7 (t_appointments, t_appointment_operations).
