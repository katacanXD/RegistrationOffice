# Шпаргалка на защиту (одна страница)

**Проект:** RegistrationOffice — сервис записи на приём. **Команда 1, ЭФБО-10-25.**

## Цифры

- 6 UC, 16 FR, 6 НФТ.
- 5 сущностей (+ роль и статус как атрибуты).
- 4 контейнера: SPA, статика, API, БД.
- 8 компонентов API.
- DFD: 7 процессов, 4 хранилища, 15 потоков.
- 9 листов A3.

## Что говорить в начале

«Мы привели документы к фактическому коду: идемпотентность, запрет пересечения записей пациента, журнал операций, создание пациента и отчёт утилизации реализованы. Границы MVP и ограничения UI указаны честно».

## Сквозная линия

Видение → UC-1…UC-6 → контекст → контейнеры → компоненты → данные → sequence → deployment → трассировка.

## Три «козырных» факта

1. **Идемпотентность:** повтор того же пациента на тот же слот — 200 и та же запись; другой пациент — 409.
2. **Пересечение:** проверка в сервисе + триггер БД на «пациент + время».
3. **Журнал:** `t_appointment_operations`, кто/когда/что/причина, в одной транзакции.

## Демо за 10 минут

1. Вход пациентом → поиск врача → слоты.
2. Запись.
3. Повтор через Swagger → `replayed=true`.
4. Другой врач, то же время → 409.
5. Перенос/отмена с причиной → history.
6. Регистратор: создание пациента через API + запись.
7. Врач: расписание.
8. Админ: «Загрузка расписания» → отчёт → CSV.

## Если спросят

- **Почему `t_users`?** Одна аутентификация и роль; минус — nullable-поля, вынесены в открытые вопросы.
- **Статус — атрибут?** Логическая модель; `t_dict_status` — физическая реализация.
- **Почему статика отдельно?** SPA отдаёт frontend/Nginx; API не доставляет статику.
- **Почему не микросервисы?** MVP, одна команда; границы компонентов позволяют выделить позже.
- **Что не входит?** Внешние интеграции, оплата, SMS, UI причины/создания пациента, графики.
- **Как проверяли?** `gradlew test` зелёный, `npm run build` успешен, ручные сценарии; триггеры PostgreSQL — на живой БД.

## Если что-то сломалось

Не спорить. Показать Swagger/curl, журнал, скриншот/видео. Если про UI — сказать: «кнопка в следующей итерации, API уже работает».
