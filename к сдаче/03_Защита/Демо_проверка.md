# Демонстрация API для защиты

Файл `demo_api.http` открывается в VS Code (REST Client) или IntelliJ HTTP Client. Подставь токены и ID после логина. Если UI подведёт, эти запросы показывают те же сценарии.

## Подготовка

1. Backend запущен, `http://localhost:8080`.
2. В базе есть врач с ID и рабочими слотами на будущую дату.
3. Логин пациента и регистратора.

## Сценарии

| № | Сценарий | Ожидание |
|---|---|---|
| 1 | Вход пациентом | 200, access token |
| 2 | Создание записи `/appointments/me` | 201, `replayed=false` |
| 3 | Повтор того же запроса | 200, `replayed=true`, тот же `appointment_id` |
| 4 | Запись к другому врачу на то же время | 409, «У пациента уже есть запись» |
| 5 | Перенос `/appointments/{id}` PATCH | 200, новое время |
| 6 | Отмена `DELETE` с причиной | 200, статус canceled |
| 7 | История `/appointments/{id}/history` | 200, created/rescheduled/canceled |
| 8 | Создание пациента `POST /patients` (registrar) | 201, роль patient |
| 9 | Отчёт `/reports/utilization` (admin) | 200, слоты/занято/утилизация |
| 10 | Экспорт `/reports/utilization/export` | `text/csv`, 5 колонок |

## Если 401

Токен истёк. Выполни логин заново и обнови переменную. Refresh-cookie обрабатывается браузером; в REST Client проще логиниться заново.

## Если 403

Проверь роль: создание пациента — `admin`/`registrar`, отчёт — `admin`, запись через `/me` — `patient`.

## Если 404

Проверь `doctorId`, `appointmentId` и дату слота. Слоты генерируются по рабочим интервалам; выходной день или перерыв дадут 400/404.
