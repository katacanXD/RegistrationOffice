# DOC-TST-001 Приемочные сценарии

| Версия | Статус | Дата обновления |
|---|---|---|
| v1.2 | Draft | 2026-04-18 |

## Сценарий 1: Регистрация и вход пациента

- Предусловие: новый пользователь не авторизован.
- Шаги: зарегистрироваться → войти → получить маршрут `/patient/main`.
- Ожидаемо: регистрация успешна, access token выдан, refresh token сохранён в cookie.

## Сценарий 2: Пациент привязывает полис и открывает поиск врача

- Предусловие: пользователь вошёл как `patient` без полиса.
- Шаги: ввести номер полиса → сохранить → открыть поиск врача.
- Ожидаемо: полис сохранён, переход к `/patient/search` доступен.

## Сценарий 3: Пациент записывается на приём

- Предусловие: пациент авторизован и полис привязан.
- Шаги: выбрать врача → выбрать дату → выбрать слот → подтвердить.
- Ожидаемо: запись создана со статусом `booked`, список записей в кабинете обновлён.

## Сценарий 4: Пациент переносит запись

- Предусловие: у пациента есть активная запись.
- Шаги: открыть карточку записи → нажать «Перенести» → выбрать новый слот → подтвердить.
- Ожидаемо: запись обновлена, пользователь возвращён в кабинет.

## Сценарий 5: Пациент отменяет запись

- Предусловие: у пациента есть активная запись.
- Шаги: открыть карточку записи → нажать «Удалить» → подтвердить в `window.confirm`.
- Ожидаемо: запись получает статус `canceled`.

## Сценарий 6: Врач просматривает расписание

- Предусловие: пользователь авторизован как `doctor`.
- Шаги: открыть `/doctor/calendar` → выбрать день → открыть занятый слот.
- Ожидаемо: отображается талон записи с ФИО пациента и полисом.

## Сценарий 7: Регистратор ищет пациента и записывает его

- Предусловие: пользователь авторизован как `registrar`.
- Шаги: найти пациента → открыть карточку → выбрать врача → выбрать слот → подтвердить.
- Ожидаемо: запись создана для выбранного пациента.

## Сценарий 8: Администратор управляет пользователями и импортом CSV

- Предусловие: пользователь авторизован как `admin`.
- Шаги: открыть панель → изменить роль пользователя → загрузить CSV.
- Ожидаемо: изменение и импорт завершаются успешно, отображается результат обработки.

## Сценарий 9: Просмотр public schedule без авторизации

- Предусловие: пользователь не авторизован.
- Шаги: открыть public endpoints врача.
- Ожидаемо: календарь и слоты врача доступны без JWT.
