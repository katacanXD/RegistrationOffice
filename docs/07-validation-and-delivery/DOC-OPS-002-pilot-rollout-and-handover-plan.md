## Подготовка к демо

1. Проверить доступность SPA и API через Nginx.
2. Подготовить учётные записи: patient, doctor, registrar, admin.
3. Убедиться, что есть тестовые врачи, пациенты и слоты.

## Демо-шаг 1: Вход и роль-маршрутизация

1. Показать login form.
2. Войти как patient и показать `/patient/main`.
3. Войти как doctor и показать `/doctor/calendar`.
4. Войти как registrar и показать `/registrar/patients`.
5. Войти как admin и показать `/admin`.

## Демо-шаг 2: Пациентский поток

1. Привязать полис.
2. Открыть поиск врача.
3. Выбрать врача и слот.
4. Подтвердить запись.
5. Показать перенос и удаление записи.

## Демо-шаг 3: Врач

1. Открыть календарь врача.
2. Показать занятый слот и талон записи.

## Демо-шаг 4: Регистратор

1. Найти пациента.
2. Открыть его карточку.
3. Выбрать врача и слот.
4. Создать запись от имени пациента.

## Демо-шаг 5: Администратор

1. Показать список пользователей.
2. Изменить роль/специальность через admin panel.
3. Загрузить CSV и показать результат обработки.

## Ожидаемый результат демо

- полный путь patient → doctor → registrar → admin;
- работающий refresh flow через cookie;
- корректные ответы API и роли;
- CSV import/export как backend capability.

## Передача по итогам демо

- `runbook` деплоя;
- список env-переменных;
- role-matrix и API-map;
- cookie-based refresh flow;
- список ограничений MVP;
- CSV форматы import/export.
