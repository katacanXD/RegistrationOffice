# DOC-STD-001 — Правила именования и версионирования документов

| Версия | Статус   | Дата создания | Дата обновления |
|--------|----------|---------------|-----------------|
| v0.1   | Approved | 2026-04-01    | 2026-04-10      |

О документе: стандарт описывает правила кодировки, именования файлов и версионирования проектных документов.

Для кого: все участники команды проекта RegistrationOffice.

---

## Кодировка документов

Каждый документ получает уникальный код вида `DOC-AREA-NNN`, где:

- `DOC` — префикс, указывающий на документ проекта;
- `AREA` — код области (см. таблицу ниже);
- `NNN` — порядковый номер документа в области (начиная с 001).

| Код области | Папка                     | Содержание                        |
|-------------|---------------------------|-----------------------------------|
| GOV         | 00-governance             | Устав, риски, команда, ретро      |
| DSC         | 01-discovery              | Предметная область, персоны       |
| REQ         | 02-requirements           | User stories, story map           |
| PLN         | 03-planning               | Реализуемость, WBS, план работ    |
| ARC         | 04-architecture           | Процессы, контекст, wireframes    |
| DAT         | 05-data-and-integration   | ERD, словарь данных, API          |
| SPC         | 06-final-specification    | Финальная спецификация            |
| OPS         | 07-validation-and-delivery| Тестирование, демо, деплой        |
| CP          | 90-checkpoints            | Контрольные срезы CP1–CP4         |
| SRC         | 98-source-materials       | Исходные материалы                |
| STD         | 99-standards              | Стандарты документации            |

## Именование файлов

Формат: `DOC-AREA-NNN-краткое-описание.md`

Примеры:
- `DOC-GOV-001-project-charter.md`
- `DOC-REQ-001-user-stories.md`
- `DOC-DAT-001-erd.md`

## Версионирование

- Версия указывается в шапке документа в формате `vX.Y`.
- Каждое существенное изменение увеличивает минорную версию (`v0.1` → `v0.2`).
- Переход к мажорной версии (`v1.0`) означает утверждение документа.

## Статусы документов

| Статус   | Значение                                      |
|----------|-----------------------------------------------|
| Draft    | Черновик, в работе                             |
| Review   | На рецензии у заказчика или преподавателя      |
| Approved | Утверждён, используется как источник истины     |
| Archived | Устарел, заменён более новой версией           |

## Шапка документа

Каждый документ начинается с:

1. Заголовок с кодом и названием.
2. Таблица: версия, статус, дата создания, дата обновления.
3. Блоки «О документе», «Для кого», «Основано на».
4. Раздел «Авторы документа».
5. Раздел «История изменений».
