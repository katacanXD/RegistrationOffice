## Основной процесс: запись пациента на прием

1. Пациент входит в систему (авторизация).
2. Пациент открывает список врачей (с фильтром по специальности).
3. Пациент выбирает врача и дату.
4. Система показывает свободные слоты на эту дату.
5. Пациент выбирает слот и подтверждает запись.
6. Система создает запись со статусом `booked`.
7. Пациент видит подтверждение и может просмотреть свои записи.

## Альтернативные потоки

### Отмена записи
- Пациент открывает свои записи.
- Выбирает запись со статусом `booked`.
- Нажимает "Отменить".
- Система переводит статус в `canceled`.

### Перенос записи
- Пациент выбирает запись для переноса.
- Выбирает новую дату и слот.
- Система проверяет доступность нового слота.
- Исходная запись переводится в `canceled`, создается новая со статусом `booked`.

### Создание записи регистратором
- Регистратор находит пациента (по логину или ФИО).
- Выбирает врача и свободный слот.
- Система создает запись от имени пациента.

## Flow по ролям

### Patient
- Авторизация → Поиск врача → Выбор слота → Запись → Управление записью → Logout

### Doctor
- Авторизация → Просмотр расписания (по дате/календарь) → Просмотр загрузки → Logout

### Registrar
- Авторизация → Поиск пациента → Выбор врача/слота → Создание записи → Logout

### Admin
- Авторизация → Управление пользователями/ролями → Просмотр логов (future) → Logout

## Критические моменты

- Проверка двойного бронирования перед созданием записи.
- Валидация, что слот находится в рабочем интервале врача.
- Слоты в перерывах не должны быть доступны.
- Завершение приема (status = `completed`) только после `slot_datetime`.
