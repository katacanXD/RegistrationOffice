## Процесс 1: Запись на приём

### Участники (пулы)
- Пациент / Регистратор
- Система RegistrationOffice
- База данных

### Описание шагов

1. **Старт**: Пациент / Регистратор инициирует запись на приём.
2. **Выбор врача и даты**: Пользователь выбирает специальность, врача и дату.
3. **Запрос доступных слотов**: Система запрашивает список свободных слотов из БД.
4. **Отображение свободных слотов**: Система показывает доступные слоты (за вычетом перерывов и уже занятых).
5. **Выбор слота**: Пользователь выбирает конкретный слот.
6. **Валидация** (шлюз — XOR):
   - Слот всё ещё свободен? → Да → п. 7
   - Слот уже занят? → Нет → Сообщение об ошибке → возврат к п. 4
7. **Проверка бизнес-правил**:
   - Слот внутри рабочего интервала врача? ✓
   - Слот не попадает в перерыв? ✓
   - Пациент существует в системе? ✓
   - Нет второй активной записи на этот слот? ✓
8. **Создание записи**: Статус = `booked`. Запись в БД.
9. **Подтверждение**: Система отображает подтверждение пользователю.
10. **Конец**.

### Условия ветвлений

- **XOR-шлюз «Слот свободен?»**: Если слот уже забронирован другим пользователем (race condition), система возвращает ошибку и предлагает выбрать другой слот.
- **XOR-шлюз «Валидации пройдены?»**: Если любая из 5 валидаций не пройдена, система возвращает описание ошибки.

## Процесс 2: Отмена записи

### Участники (пулы)
- Пациент / Регистратор
- Система RegistrationOffice

### Описание шагов

1. **Старт**: Пользователь инициирует отмену записи.
2. **Выбор записи**: Пользователь выбирает запись из списка активных (status = `booked`).
3. **Указание причины** (для регистратора): Регистратор указывает причину отмены.
4. **Обновление статуса**: Запись переводится в status = `canceled`.
5. **Логирование**: Фиксируется кто, когда и по какой причине отменил запись.
6. **Подтверждение**: Пользователь получает подтверждение отмены.
7. **Конец**.

---

## Процесс 3: Перенос записи

### Участники (пулы)
- Пациент / Регистратор
- Система RegistrationOffice

### Описание шагов

1. **Старт**: Пользователь инициирует перенос записи.
2. **Выбор текущей записи**: Пользователь выбирает запись для переноса.
3. **Выбор нового слота**: Система показывает свободные слоты того же врача.
4. **Валидация нового слота**: Аналогично процессу записи (п. 6-7 Процесса 1).
5. **Отмена исходной записи**: Исходная запись → status = `canceled`, причина = «перенос».
6. **Создание новой записи**: Новая запись → status = `booked`.
7. **Логирование**: Фиксируется связь «перенос из записи X в запись Y».
8. **Подтверждение**: Пользователь получает подтверждение переноса.
9. **Конец**.

## Точки принятия решений

| Шлюз               | Тип  | Описание                                                    |
|---------------------|------|-------------------------------------------------------------|
| Слот свободен?      | XOR  | Проверка на двойное бронирование                            |
| Валидации пройдены? | XOR  | Проверка всех 5 бизнес-правил                               |
| Есть свободные слоты?| XOR | Есть ли доступные слоты у выбранного врача на выбранную дату|

## Исключения

- Если пациент не найден в системе → предложение зарегистрироваться.
- Если нет свободных слотов → предложение выбрать другую дату или другого врача.
- Если сервер недоступен → сообщение об ошибке с просьбой повторить позже.
