## Общие принципы

- Интерфейс адаптивный: desktop (1280px+) и мобильная версия (375px).
- Навигация через боковое меню (sidebar) — набор пунктов зависит от роли.
- Все формы имеют валидацию на стороне клиента перед отправкой на сервер.
- Ошибки отображаются inline под полями и как toast-уведомления.

## Экран 1: Логин / Регистрация

**Сценарий:** Все роли — вход в систему.

**Состав:**
- Форма логина: поля `username`, `password`, кнопка «Войти».
- Ссылка «Зарегистрироваться» → форма регистрации (username, password, роль).
- При ошибке — inline-сообщение под формой.

**API:** `POST /api/auth/login`, `POST /api/auth/register`

---

## Экран 2: Выбор врача и даты

**Сценарий:** Пациент/Регистратор записывается на приём (шаги 1-2).

**Состав:**
- Фильтр по специальности (dropdown).
- Список врачей: ФИО, специальность — карточки.
- При выборе врача → появляется календарь с доступными датами.
- Даты с доступными слотами подсвечены зелёным.

**API:** `GET /api/doctors`, `GET /api/work-slots?doctorId=...&date=...`

---

## Экран 3: Календарь слотов

**Сценарий:** Пациент/Регистратор выбирает конкретный слот (шаг 3-4).

**Состав:**
- Сетка слотов на выбранную дату: время начала, длительность.
- Свободные слоты — зелёные, кликабельные.
- Занятые — серые, некликабельные.
- Перерывы — отмечены штриховкой.
- При клике на слот → модальное окно подтверждения.

**API:** `GET /api/work-slots?doctorId=...&date=...`, `GET /api/appointments?doctorId=...&date=...`

---

## Экран 4: Подтверждение записи

**Сценарий:** Пациент/Регистратор подтверждает бронирование (шаг 5-6).

**Состав:**
- Модальное окно: врач, дата, время, ФИО пациента.
- Кнопки: «Записаться» (primary), «Отмена» (secondary).
- При успехе → toast «Запись создана» + редирект на «Мои записи».
- При ошибке (двойное бронирование) → toast с описанием.

**API:** `POST /api/appointments`

---

## Экран 5: Мои записи (Пациент)

**Сценарий:** Пациент просматривает, переносит или отменяет записи.

**Состав:**
- Таблица/список: дата, время, врач, специальность, статус (badge).
- Статусы: `booked` (синий), `completed` (зелёный), `canceled` (серый).
- Кнопки на каждой записи со статусом `booked`: «Перенести», «Отменить».
- «Отменить» → модальное окно с полем «Причина».
- «Перенести» → переход на экран 3 (выбор нового слота).

**API:** `GET /api/appointments?patientCode=...`, `PUT /api/appointments/{id}/cancel`, `PUT /api/appointments/{id}/reschedule`

---

## Экран 6: Расписание врача (день/неделя)

**Сценарий:** Врач/Регистратор/Админ видит расписание.

**Состав:**
- Переключатель «День» / «Неделя».
- День: вертикальная сетка с временными слотами, заполненные — с ФИО пациента.
- Неделя: горизонтальная сетка 7 колонок, слоты как цветные ячейки.
- Клик на запись → детали (ФИО, статус, кнопка «Завершить приём»).

**API:** `GET /api/appointments?doctorId=...&date=...`

---

## Экран 7: Управление записями (Регистратура)

**Сценарий:** Регистратор ищет и управляет записями всех врачей.

**Состав:**
- Поиск: по ФИО пациента, по врачу, по дате.
- Таблица результатов: дата, время, врач, пациент, статус.
- Действия: «Отменить», «Перенести» — аналогично экрану 5.

**API:** `GET /api/appointments?doctorId=...&date=...&status=...`

---

## Экран 8: Настройка расписания (Админ)

**Сценарий:** Администратор создаёт рабочие интервалы.

**Состав:**
- Выбор врача (dropdown).
- Форма: дата, время начала, время окончания, длительность слота (мин), перерыв (начало, конец).
- Кнопка «Создать» → генерация слотов.
- Кнопка «Импорт CSV» → переход на экран 10.
- Превью: список сгенерированных слотов перед сохранением.

**API:** `POST /api/work-slots`

---

## Экран 9: Отчёт утилизации (Админ)

**Сценарий:** Администратор анализирует загрузку.

**Состав:**
- Фильтры: период (от–до), врач, специальность.
- Таблица: врач, дата, slots_total, slots_booked, slots_canceled, utilization %.
- Визуализация: bar chart утилизации по дням.
- Кнопка «Экспорт CSV».

**API:** `GET /api/reports/utilization?from=...&to=...`, `GET /api/reports/utilization/export-csv`

---

## Экран 10: Импорт CSV (Админ)

**Сценарий:** Массовая загрузка расписания.

**Состав:**
- Drag-and-drop зона для CSV-файла.
- Превью первых 5 строк.
- Кнопка «Загрузить».
- Результат: «Импортировано: N, пропущено: M».
- Повторная загрузка того же файла → пропущены дубли (идемпотентность).

**API:** `POST /api/work-slots/import-csv`
