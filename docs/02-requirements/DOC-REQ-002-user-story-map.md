## Структура карты

Карта организована по горизонтальной оси (активности пользователей) и вертикальной оси (уровень приоритета / релиз).

### Активности верхнего уровня

| Активность                | Роль           | Описание                                     |
|---------------------------|----------------|----------------------------------------------|
| Просмотр расписания       | Все роли       | Просмотр доступных слотов и записей           |
| Запись на приём            | Пациент, Регистратор | Бронирование свободного слота            |
| Управление записью        | Пациент, Регистратор | Перенос и отмена записи                  |
| Управление расписанием    | Администратор  | Настройка интервалов, перерывов, слотов       |
| Отчётность и аналитика    | Администратор  | Утилизация, экспорт CSV                       |
| Аутентификация            | Все роли       | Вход, регистрация, управление токенами        |

## Логика декомпозиции

Декомпозиция построена от основного пользовательского сценария: пациент видит расписание → записывается → при необходимости управляет записью. Параллельно администратор настраивает расписание и контролирует загрузку. MVP включает минимально необходимый набор для полного цикла «просмотр → запись → отчёт».
