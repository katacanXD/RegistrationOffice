## Сценарий 1: Пациент записывается на приём

**Роль:** Пациент
**Цель:** Записаться к нужному врачу на удобное время.

| Шаг | Действие пользователя              | Реакция системы                              |
|-----|-------------------------------------|----------------------------------------------|
| 1   | Открывает страницу записи           | Показывает список специальностей              |
| 2   | Выбирает специальность              | Показывает список врачей этой специальности   |
| 3   | Выбирает врача                      | Показывает календарь с доступными датами      |
| 4   | Выбирает дату                       | Показывает свободные слоты (за вычетом перерывов и занятых) |
| 5   | Нажимает на слот                    | Открывает форму подтверждения                 |
| 6   | Нажимает «Записаться»               | Валидация → создание записи → подтверждение   |

**Альтернативный поток:** Если слот уже занят (race condition) → сообщение «Слот занят, выберите другой».

## Сценарий 2: Пациент отменяет запись

**Роль:** Пациент
**Цель:** Освободить слот, если не может прийти.

| Шаг | Действие пользователя              | Реакция системы                              |
|-----|-------------------------------------|----------------------------------------------|
| 1   | Открывает «Мои записи»             | Показывает список активных записей (booked)   |
| 2   | Нажимает «Отменить» на записи      | Открывает форму с полем «Причина»             |
| 3   | Заполняет причину, подтверждает     | status → canceled, логирование, подтверждение  |

---

## Сценарий 3: Пациент переносит запись

**Роль:** Пациент
**Цель:** Перенести приём на другое время.

| Шаг | Действие пользователя              | Реакция системы                              |
|-----|-------------------------------------|----------------------------------------------|
| 1   | Открывает «Мои записи»             | Список активных записей                       |
| 2   | Нажимает «Перенести»               | Показывает свободные слоты того же врача      |
| 3   | Выбирает новый слот                 | Валидация нового слота                        |
| 4   | Подтверждает                        | Старая запись → canceled, новая → booked       |

## Сценарий 4: Врач смотрит расписание

**Роль:** Врач
**Цель:** Видеть, кто записан на сегодня/неделю.

| Шаг | Действие пользователя              | Реакция системы                              |
|-----|-------------------------------------|----------------------------------------------|
| 1   | Входит в систему                    | Автоматически открывается «Моё расписание»    |
| 2   | Выбирает дату или неделю            | Показывает сетку слотов с ФИО пациентов       |
| 3   | Нажимает на запись                  | Показывает детали: ФИО, статус, время          |
| 4   | После приёма нажимает «Завершить»   | status → completed (если время наступило)      |

## Сценарий 5: Регистратор записывает пациента

**Роль:** Регистратура
**Цель:** Записать пациента по звонку.

| Шаг | Действие пользователя              | Реакция системы                              |
|-----|-------------------------------------|----------------------------------------------|
| 1   | Выбирает врача и дату               | Показывает свободные слоты                    |
| 2   | Ищет пациента по ФИО                | Находит или предлагает создать нового          |
| 3   | Выбирает слот                       | Форма подтверждения                           |
| 4   | Нажимает «Записать»                 | Валидация (5 проверок) → запись создана        |

**Альтернативный поток:** Двойное бронирование → ошибка «Слот уже занят».

## Сценарий 6: Регистратор переносит/отменяет запись

**Роль:** Регистратура
**Цель:** Обработать просьбу пациента по телефону.

| Шаг | Действие пользователя              | Реакция системы                              |
|-----|-------------------------------------|----------------------------------------------|
| 1   | Ищет запись по ФИО пациента или врачу| Список записей                               |
| 2   | Нажимает «Отменить» или «Перенести» | Форма с причиной / выбор нового слота         |
| 3   | Подтверждает                        | Логирование: кто, когда, причина              |

## Сценарий 7: Администратор настраивает расписание

**Роль:** Администратор
**Цель:** Задать рабочие интервалы врача.

| Шаг | Действие пользователя              | Реакция системы                              |
|-----|-------------------------------------|----------------------------------------------|
| 1   | Выбирает врача                      | Показывает текущее расписание                 |
| 2   | Нажимает «Добавить интервал»        | Форма: дата, время начала/конца, длина слота, перерыв |
| 3   | Заполняет и сохраняет               | Генерация слотов (за вычетом перерыва)        |
| 4   | Или загружает CSV                   | Импорт (идемпотентный — дубли пропускаются)   |

## Сценарий 8: Администратор смотрит отчёт утилизации

**Роль:** Администратор
**Цель:** Оценить загрузку врачей и найти «окна».

| Шаг | Действие пользователя              | Реакция системы                              |
|-----|-------------------------------------|----------------------------------------------|
| 1   | Открывает «Отчёты»                 | Форма фильтров: период, врач, специальность   |
| 2   | Задаёт фильтры, нажимает «Показать»| Таблица: врач, дата, total, booked, canceled, utilization % |
| 3   | Нажимает «Экспорт CSV»             | Скачивается файл CSV                          |
