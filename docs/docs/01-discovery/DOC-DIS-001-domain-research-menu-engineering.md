## Цель исследования

Понять ключевые процессы и ограничения для MVP цифровой регистратуры с учетом будущего frontend-клиента.

## Ключевые участники

- Пациент: ищет врача, записывается, управляет своими записями.
- Врач: смотрит расписание, список приемов.
- Регистратор: помогает пациентам, управляет пользователями и записями.
- Администратор: управляет доступами и пользователями.

## Основные процессы

1. Аутентификация и вход в систему.
2. Поиск врача и просмотр доступных слотов.
3. Создание/перенос/отмена записи.
4. Просмотр личного профиля и данных пользователя.

## Ограничения MVP

- только веб-интерфейс (frontend) + backend API;
- без интеграции с гос.системами в первой версии;
- без мобильных приложений;
- без платежного контура.

## Выводы для архитектуры

- нужна единая role-matrix для frontend/backend;
- API-контракты должны быть стабильны и версионированы;
- критичны приемочные сценарии по записи на прием и правам доступа.
