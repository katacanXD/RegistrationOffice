О документе: фиксирует цель, границы, этапы и критерии успеха проекта RegistrationOffice.

## 1. Контекст и проблема

Пациентам, врачам и регистратуре нужен единый цифровой контур для записи на прием, просмотра расписания и управления приемами. Сейчас процессы часто фрагментированы между звонками, таблицами и локальными системами, что увеличивает ошибки и время обслуживания.

## 2. Цель проекта

Собрать MVP медицинской регистратуры как fullstack-систему:

- backend API с авторизацией и ролевым доступом;
- frontend для основных сценариев ролей;
- прозрачная модель данных и воспроизводимый деплой.

## 3. In scope

- аутентификация (`login`, `registration`, `refresh`, `logout`);
- роли `admin`, `registrar`, `doctor`, `patient`;
- управление пользователями и профилем;
- расписание и слоты врача;
- создание и управление записями на прием;
- frontend-экраны под ключевые сценарии ролей;
- документация, тестовые сценарии и деплой-руководство.

## 4. Out of scope

- телемедицина и видеозвонки;
- интеграция с государственными системами в первой версии;
- мобильные приложения в MVP;
- биллинг и страховые расчеты.

## 5. Критерии успеха

- backend API покрывает базовые бизнес-сценарии;
- frontend реализует пользовательские потоки для 4 ролей;
- модель данных и контракты согласованы с реализацией;
- деплой на VM воспроизводится по runbook;
- приемочные сценарии выполняются на демо-среде.

## 6. Этапы

| Этап | Фокус |
|---|---|
| CP1 | Устав, discovery, первичные требования |
| CP2 | Архитектура, сценарии и UX-каркас frontend |
| CP3 | Данные, API-контракты, интеграционный контур |
| CP4 | Финальная спецификация, тесты, демо и передача |
