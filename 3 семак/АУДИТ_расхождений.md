# Аудит расхождений: код ↔ docs ↔ ПЗ

**Проект:** RegistrationOffice
**Ветка:** `hk_1-3`
**Дата:** 13.11.2026
**Назначение:** рабочая матрица для этапов A–E. Источник истины — код и схема БД; `docs/` и ПЗ — производные.

---

## 1. Сводка

- Подтверждено **20 расхождений**.
- **5** закрываются доработками кода: идемпотентность, пересечение записей пациента, журнал операций, создание пациента, отчёт утилизации.
- **5** закрываются новыми документами практических: «Сценарии использования», «Контекст системы», «Контейнеры системы», «Компоненты контейнера», «Модель данных».
- Остальные — правки текста, диаграмм, дат и внешние проверки.
- Главный принцип: в ПЗ не остаётся утверждений, которые нельзя подтвердить кодом или пометить «не реализовано / вне MVP».

## 4. Открытые вопросы продукта

1. Должен ли полис быть уникальным? Сейчас нет; CSV может создать дубль.
2. Обязателен ли хотя бы один рабочий слот у врача? Сейчас нет.
3. Специальность — свободная строка или справочник? Сейчас строка.
4. Что происходит при удалении пользователя с записями? FK-поведение не задано.
5. Нужна ли причина отмены в UI? Пока API-only; UI — следующая итерация.
6. «Пересечение» записей пациента — совпадение времени или интервалов? Принято: совпадение даты и времени слота.
7. Отчёт утилизации — только админ или ещё регистратор? Принято: админ.

## 5. Правила синхронизации

1. Любое утверждение в `docs/` и ПЗ имеет статус: **реализовано** / **не реализовано (вне MVP)** / **открытый вопрос**.
2. Порядок: код → `docs/` → ПЗ. Не наоборот.
3. Одинаковые ID во всех документах: UC-1…6, НФТ-1…6, FR-01…16, K1…K7, C1…C12, P1…P9, сущности 1–5.
4. Даты в документах — не позже 13.11.2026; пакет v2 — 07.11.2026.
5. Одна ветка `hk_1-3`; `master` не трогаем.
6. После правки DOCX — перегенерировать PDF и A3; версии не должны расходиться.
