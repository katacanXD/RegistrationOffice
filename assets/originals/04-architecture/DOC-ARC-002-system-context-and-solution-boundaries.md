## Контекстная диаграмма (текстовое описание)

### Система: RegistrationOffice

Веб-система записи на приём с отдельными интерфейсами для пациента, врача, регистратора и администратора.

### Внешние акторы

| Актор         | Взаимодействие с системой                                   |
|---------------|-------------------------------------------------------------|
| Пациент       | Вход, привязка полиса, поиск врача, запись, перенос, отмена |
| Врач          | Просмотр своего расписания и талонов                        |
| Регистратор   | Поиск пациента, запись/перенос от имени пациента            |
| Администратор | Управление пользователями, импорт CSV                       |

### Внешние системы

| Система          | Назначение                 | Статус в MVP |
|------------------|----------------------------|--------------|
| PostgreSQL       | Хранение данных            | Входит       |
| Nginx            | Reverse proxy и отдача SPA | Входит       |
| Yandex Cloud VM  | Среда размещения           | Входит       |
| ЕМИАС / SMS / 1С | Внешние интеграции         | Не входят    |

## Границы MVP

### Входит в MVP

1. Авторизация, регистрация и JWT refresh flow.
2. Кабинет пациента с полисом и списком записей.
3. Поиск врача и запись на слот.
4. Перенос и отмена записи.
5. Кабинет врача с расписанием и карточкой талона.
6. Регистраторские сценарии поиска пациента, записи и переноса.
7. Админская панель пользователей и CSV import для doctors, patients, appointments, work-slots.
8. REST API на `/api/v1/**` и деплой в Docker Compose.

### Не входит в MVP

- Отдельный экран отчётов утилизации.
- Визуальная настройка расписания вручную через форму.
- Push/SMS/email уведомления.
- Мобильное приложение.
- Интеграции с внешними МИС.
- Электронная медицинская карта и клинические данные.

## Архитектура (высокоуровневая)

```
┌─────────────┐     ┌──────────────────────────────────┐     ┌──────────────┐
│   Browser   │────▶│ Nginx + React SPA                │────▶│ PostgreSQL   │
│ (web UI)    │◀────│ Spring Boot API (`/api/v1/**`)   │◀────│              │
└─────────────┘     └──────────────────────────────────┘     └──────────────┘
                               │
                         Docker Compose / VM
```

### Компоненты

| Компонент | Технология         | Назначение                                  |
|-----------|--------------------|---------------------------------------------|
| Frontend  | React + Vite       | UI для всех ролей                           |
| Backend   | Spring Boot (Java) | API, бизнес-логика, JWT, валидация          |
| API proxy | Nginx              | Маршрутизация и отдача SPA                  |
| Database  | PostgreSQL         | Пользователи, записи, слоты, refresh tokens |
| Infra     | Docker Compose     | Запуск всего контура на одной VM            |

## Практические границы фронтенда

- В UI нет sidebar; навигация идёт через отдельные страницы и ссылки «Назад».
- Экран отчёта утилизации в frontend отсутствует, хотя CSV export-эндпоинты есть на backend.
- Базовый сценарий пациента начинается с проверки и привязки полиса ОМС.
- Для переноса записи используется тот же календарный экран, что и для создания записи.
