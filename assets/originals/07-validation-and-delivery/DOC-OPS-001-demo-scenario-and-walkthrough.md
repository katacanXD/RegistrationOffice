## Проверки (ключевые)

### TC-001: Регистрация и вход

- Предусловие: пользователь не авторизован.
- Шаги: зарегистрироваться → войти.
- Ожидаемо: выдаётся access token, refresh token попадает в cookie, маршрут зависит от роли.

### TC-002: Привязка полиса пациента

- Предусловие: пациент вошёл без полиса.
- Шаги: ввести полис → сохранить.
- Ожидаемо: полис сохраняется, доступ к поиску врача появляется.

### TC-003: Запись на приём пациентом

- Предусловие: пациент вошёл и полис привязан.
- Шаги: выбрать врача → дату → слот → подтвердить.
- Ожидаемо: запись создана со статусом `booked`.

### TC-004: Перенос записи

- Предусловие: есть активная запись.
- Шаги: нажать «Перенести» → выбрать новый слот → подтвердить.
- Ожидаемо: запись обновлена, пользователь возвращён в кабинет.

### TC-005: Отмена записи

- Предусловие: есть активная запись.
- Шаги: нажать «Удалить» → подтвердить.
- Ожидаемо: запись получает статус `canceled`.

### TC-006: Просмотр расписания врача

- Предусловие: вход как `doctor`.
- Шаги: открыть календарь → кликнуть занятый слот.
- Ожидаемо: открывается талон с данными пациента.

### TC-007: Регистратор записывает пациента

- Предусловие: вход как `registrar`.
- Шаги: найти пациента → выбрать врача → выбрать слот → подтвердить.
- Ожидаемо: запись создаётся для выбранного пациента.

### TC-008: Админский CSV import

- Предусловие: вход как `admin`.
- Шаги: загрузить CSV для doctors/patients/appointments/work-slots.
- Ожидаемо: отображается результат обработки файла.

### TC-009: Public расписание без авторизации

- Предусловие: пользователь не вошёл.
- Шаги: вызвать public calendar/slots врача.
- Ожидаемо: данные доступны без JWT.
