# Кейс 7) График приёмов врача

## Отрасль
Здравоохранение

## Бизнес-цель
Повысить утилизацию расписания (доля занятых слотов) и снизить «окна».

## KPI
Утилизация = занятые слоты / доступные слоты за период; целевое значение задаётся для Т1.

## Расширенное описание

Смоделируйте расписание врачей с рабочими интервалами, длительностью слотов и перерывами. Обеспечьте запись/перенос/отмену и отчёт загрузки по врачу/дате.

## Данные (синтетика; схема)

Таблицы:
- `doctors` (doctor_id, fio, specialty)
- `work_slots` (doctor_id, date, start_time, end_time, slot_minutes, break_start, break_end)
- `appointments` (appt_id, doctor_id, slot_datetime, status ∈ {booked, canceled, completed}, patient_code)
- `patients` (patient_code, fio, birth_year)

Объёмы: ≥100 слотов, ≥50 записей.

## Валидации (≥5)
1. Отсутствие двойного бронирования.
2. Слоты внутри рабочего интервала.
3. Перерывы не бронируются.
4. Корректный статус.
5. Ссылки на существующего врача/пациента.

## Основные бизнес-правила

### Рабочее время и слоты
- Для каждого врача задаются рабочие интервалы (дата, start_time–end_time) и длина слота (slot_minutes).
- Перерывы (break_start–break_end) внутри интервала считаются «недоступными» и не попадают в слоты.
- Слоты генерируются только внутри рабочего интервала за вычетом перерывов.

### Операции с записями
- Статусы appointments: {booked, canceled, completed}.
- Запрет двойного бронирования: слоту может соответствовать максимум одна активная запись (booked).
- Перенос: допускается на свободный слот того же врача; исходная запись переводится в canceled.

### Метрики и KPI
- Утилизация за период: slots_booked / slots_total.
- Отчёт по врачу/дате/специальности; команда задаёт целевое значение на Т1.

## Нефункциональные требования
- Производительность: построение отчёта утилизации по ≥100 слотам и ≥50 записям — интерактивно.
- Надёжность: повторная загрузка CSV для work_slots/appointments идемпотентна.
- Трассируемость: лог операций (кто/когда создал/перенёс/отменил), причина отмены/переноса.

## Роли
- Пациент — просмотр доступных слотов, запись на приём, отмена, перенос своей записи.
- Врач — просмотр своего расписания и списка записей.
- Регистратура — управление записями всех врачей, запись, перенос, отмена.
- Администратор — управление сеткой расписания, правами доступа и справочниками.

## Технологический стек
- База данных: PostgreSQL.
- Backend: Spring Boot (Java).
- Frontend: React (JavaScript), HTML, CSS.
- Инфраструктура: Docker Compose, Nginx.

## Ожидаемые артефакты
- Реализованные формы «Расписание врача» и «Запись на приём», отчёт «Загрузка расписания».
- Настроенный импорт CSV для work_slots и appointments.
- UI-прототип календаря (день/неделя).
- Описание сценария демо (создание слотов, запись, отмена, отчёт).

## Критерии приёмки
1. Реализованы правила слотов (длительность, перерыв, запрет двойного бронирования).
2. Построен отчёт загрузки по врачу/периоду с расчётом утилизации.
3. Экспорт отчёта в CSV (doctor_id, date, slots_total, slots_booked, utilization).
4. Наличие README со шагами запуска и проверки.
